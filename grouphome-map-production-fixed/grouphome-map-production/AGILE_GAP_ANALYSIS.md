# 우슐랭 레퍼런스 대비 그룹홈맵 갭 분석

## 레퍼런스에서 배울 점

우슐랭은 첫 화면부터 지도와 리스트가 동시에 열리는 앱형 탐색 경험이다. 사용자는 설명을 읽기 전에 바로 필터, 검색, 지도 이동, 카드 선택을 한다. 핵심 완성도는 장식보다 즉시성, 상태 피드백, 조작 밀도에서 나온다.

## 현재 부족한 점

1. 지도 앱으로서의 첫 인상  
   그룹홈맵은 스토리 페이지 구조가 강하고, 실제 탐색기는 아래에 있다. 공공 캠페인 페이지로는 좋지만 지도 서비스처럼 바로 쓰는 느낌은 약하다.

2. 지도 완성도 — ✅ 지오코딩 완료(2025-xx 갱신), JS 키는 재발급 대기
   REST 지오코딩은 520개 중 518개 주소 좌표 확보, 2개는 시군구 중심 대체 좌표로 완료됨(`geocoding_failures.json` 참고).
   Kakao JavaScript 키는 노출 이력으로 폐기·플레이스홀더 처리했으므로, 배포 전 재발급 및 도메인 제한만 남은 상태다(README.md "Kakao API 키 적용" 참고).

3. 탐색 피드백  
   기존 버전은 지역/검색/정렬은 되지만, 현재 몇 건 중 몇 건을 보고 있는지, 어떤 필터가 빠르게 걸렸는지, 카드 선택 결과가 무엇인지가 즉시 드러나지 않았다.

4. 반복 사용성  
   우슐랭에는 즐겨찾기, 권역 탭, 내 주변, 세부 필터가 있다. 그룹홈맵에는 사용자가 다시 볼 시설을 임시로 모아두는 흐름이 없었다.

5. 콘텐츠 밀도  
   우슐랭 카드에는 카테고리, 위치, 추천 문장, 가격 같은 판단 단서가 있다. 그룹홈맵은 민감한 시설 데이터라 홍보 문장은 만들 수 없지만, 빈자리·정원·시대구분·확인 필요 같은 실제 판단 단서를 더 드러낼 필요가 있다.

## 이번 스프린트에서 실행한 것

- 탐색기 상단에 `Live Explorer` 상태와 `현재 표시 / 전체` 카운트 추가
- 관심 시설 저장 및 관심 필터 추가
- 빈자리 있음, 만실, 최근 5년, 정원 7명, 확인 필요 빠른 필터 추가
- 리스트 카드에 빈자리·정원·시대구분·확인 필요 태그 추가
- 카드 클릭 시 지도 키가 없어도 보이는 선택 시설 상세 패널 추가
- Kakao 키 미입력 상태에서도 데이터 좌표 분포를 보여주는 미니 프리뷰 추가

## 다음 스프린트 우선순위

1. ~~Kakao REST 지오코딩 완료~~ — 완료 (518/520 주소 좌표, 2건 대체 좌표)
   잔여 2건(부산 강서구 열린그룹홈, 부천시 맑은샘우리집)은 원문 주소 자체를 재확인해 수동 보정 여지가 있는지 검토.

2. Kakao JavaScript 키 재발급 및 도메인 제한 등록 — **진행 필요**
   기존 키는 노출 이력으로 폐기함. 새 키 발급 → 플랫폼 > Web에 배포 도메인+`localhost:8080` 등록 → `set-kakao-js-key-windows.cmd`로 `GROUPHOME_MAP_CONFIG.kakaoJavaScriptKey` 교체.

3. 지도 우선 진입 옵션  
   기존 히어로-타임라인 구조를 유지하되, 첫 화면에 `지도 바로 탐색` CTA와 탐색기 앵커 진입을 강화한다. 실제 서비스용 별도 `/map` 단일 앱 화면도 고려한다.

4. 고급 필터 드로어  
   정원 규모, 설치 시기, 빈자리 범위, 종사자수 범위를 하나의 접이식 세부 필터로 묶는다.

5. 모바일 앱화  
   모바일에서는 리스트/지도 탭 전환을 제공해 긴 상하 스택보다 빠르게 탐색하게 한다.

6. 운영 품질  
   지도 로딩 실패, 좌표 실패, 데이터 갱신일, 접근성, 사용량 분석 이벤트를 명확히 붙인다.
